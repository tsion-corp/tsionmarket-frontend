# Chain reads move from Alchemy to dRPC

Every plain JSON-RPC read the server makes now goes to dRPC instead of
Alchemy:

- **EVM reads:** the fallback behind ZeroDev in `lib/server/evm-read.ts`,
  which also serves the `/api/evm-rpc/[network]` proxy.
- **Solana RPC:** `lib/server/solana-rpc-upstreams.ts`, now Helius → dRPC →
  public.
- **Solana activity reads:** `getSignaturesForAddress` and `getTransaction`
  in `lib/server/activity.ts`.

The dRPC key comes from `DRPC_API_KEY`, a server-only env var and the same
credential worldstreet-crypto-backend uses. **It must be set on the server
before deploy:** without it, EVM reads that ZeroDev can't serve fail with
"No read provider", and Solana falls back to Helius and the public node. The
network mapping (41 networks plus Solana) was verified live with
`eth_chainId`.

dRPC doesn't serve shape, gensyn, polynomial or stable-testnet, so those
read only through ZeroDev and fail with "No read provider" if ZeroDev can't
serve them.

**Still on Alchemy,** because dRPC has no API for them:

- token prices;
- token metadata (`alchemy_getTokenMetadata`);
- EVM transfer history (`alchemy_getAssetTransfers`);
- portfolio discovery (Alchemy Portfolio API);
- the gas-sponsorship bundler on non-Base chains.

Verified with the updated read-pool, proxy, Solana-upstream and activity
tests, plus a new `lib/server/drpc.test.ts`.
